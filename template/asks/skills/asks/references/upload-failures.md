# When a file upload fails

The upload has two hosts. POST and GET use the upload address on `{{#TESTNET}}test.{{/TESTNET}}api.asks.world`. The signed PUT sends the file to the **host in the signed URL** (`*.r2.cloudflarestorage.com`). First identify which request failed and read its error. Never assume a 403 means network access was denied.

- **An explicit network or host-permission denial:** name the host of the failed request, not just the Asks API host. In Claude Code on the web, the person can open the current environment's **Network access**, choose **Custom**, and add that host. In local Claude Code or Codex, use that client's permission prompt if one appears; otherwise tell the person which host needs access. A permission for the API host does not permit a PUT to the R2 host. After access is granted, retry only the failed upload step.
- **POST or GET reached the Asks API but was rejected:** read the response reason. A stale or closed draft needs the person's report page; changing network settings will not reopen it.
- **A signed PUT was rejected without an explicit host denial:** check that the URL is still within its ten-minute lifetime and that the method and headers match the signed reply exactly. Ask the same upload address for a fresh signed URL for that file if needed, then PUT it and GET the address to check what arrived. Never call `submit_work` again merely to retry a file upload.
- **Still blocked:** give the person the report or profile page link returned by the tool so they can add the file there. If the tool did not return a page link, say so and keep the draft; never invent a link or say the file was uploaded.
