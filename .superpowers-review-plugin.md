## Findings, ranked

### Critical (in the MCP PR `s6/asks-mcp`, blocks this plugin end to end)

1. **`set_payout_settings` and `create_campaign` get a broken schema under the network wrapper.**
   `server.ts:199` builds `inputSchema: { network: networkInput, ...config.inputSchema }`, but these two
   pass a `z.object(...).strict()` instance, not a raw shape (`server.ts:2866` `settingsInput`,
   `server.ts:2927` `campaignInput`). Spreading a zod v4 object gives `def`, `type`, `toJSONSchema`...
   (checked: `Object.keys({n, ...z.object({a}).strict()})` → `n, toJSONSchema, def, type, …`). So the
   company payouts step (`company.md:185-191`, `account/SKILL.md:50`) and own-rules campaigns
   (`create/SKILL.md:64-67`) cannot work. Fix in the MCP: pass `.shape` (and keep strictness in the
   handler), or unwrap ZodObject in the wrapper.

### High

2. **IXO staff told to approve check requests with `decide_check`; the tool never does that.**
   `manage/SKILL.md:45-47`: "`decide_check` approve (with a short line on what was checked)". `tools.ts:354`:
   "Approving IXO's checks is never done here: an IXO approver approves on the website's check requests
   page"; `check_requests` output says the same (`server.ts:~4280`), and a boot test pins it. Copied from
   the old specialist skill. Fix: decline here; approve → point them to the website's check-requests page.

3. **Sign-in safety rule became ambiguous.** `create/references/company.md:68`: "If it isn't clearly
   theirs, don't use it or delete it." Old rule: "don't use it **and don't delete it**: on a shared
   computer it is someone else's sign-in". The new wording can be read as "either don't use it, or delete
   it". Fix: "don't use it and don't delete it."

### Medium

4. **No site URL anywhere.** `company.md:36` defines `<site>` as "the asks.world website the tools' links
   point to", then needs it for `curl -s <site>/api/oracles` (`:81`) and the settings page (`:105`).
   `manage/SKILL.md:22` says "Open <the link>" for the final-OK page with no link source (old: `<site>/me`).
   The agent will guess a domain. Fix: give mainnet/testnet site URLs once (or "the site in a tool's
   link / `my_status`") in `company.md`, and name the page in `manage`.

5. **Network for follow-up skills is undefined in a fresh session.** `invite/SKILL.md:8-9`,
   `manage/SKILL.md:8-9`, `report/SKILL.md:8-9`: "the one the ask was posted on". After a restart the
   agent can't know it. Fix, one line: "mainnet unless they said it was a dry run; if the ask isn't
   found there, look on testnet and say so."

6. **Two asks plugins installed (asks + asks-dev) is not covered.** The old skills had "two plugins
   installed? ... never mix the two in one job". The renames make this likely for the team
   (`ixo-openhands` → `asks`, `ixo-openhands-test` → `asks-dev`). `connect/SKILL.md:27-31` only covers
   hand-added servers. Fix: one line in `asks/SKILL.md` "use only this plugin's server's tools".

7. **`/asks-dev` entry command probably does not exist.** The entry skill is `name: asks` in both
   plugins (`plugins/asks-dev/skills/asks/SKILL.md:2`), so in asks-dev it is `/asks-dev:asks`, yet
   `plugins/asks-dev/skills/help/SKILL.md:24` and `plugins/asks-dev/README.md:9` say `/asks-dev`. Also not
   verified that a skill named like its plugin is callable as bare `/asks` (spec assumes it). Check in a
   real session; if not, the help table and README should say `/asks:asks` (or rename).

8. **The MCP still names the old plugins and the old brand** (MCP PR, but user-visible through this
   plugin). `tools.ts:443` (`where_to_act`: "OpenHands HQ plugin (ixo-openhands-hq)"),
   `packages/openhands-sdk/src/data/install.ts:284-300` (install lines for ixo-openhands / -hq / -test),
   and tool descriptions "Openhands Network" / "Openhands" (`tools.ts:111,119,202`). The agent echoes
   these. Fix in the MCP before publish, or the hosted connector sends people to removed plugins.

### Low

9. **Report key names not given for two sections.** `report/SKILL.md:37,40` calls them "Problems" and
   "What to do"; the schema keys are `findings` and `recommendations` (`reportSubmit.ts:27`). The tool
   description has them, so it's recoverable, but one word each avoids a refused first call.

10. **Coin choice.** Tools say "Ask the person which coin pays" (post_cleanup, organise_campaign,
    draft_call, draft_plan). `create/SKILL.md:17-18` only says IXO, USDC possible on mainnet. Fine on

11. **Small money-preview gaps.** `create/SKILL.md:61-63`: the cleanup Say has no "real/play money";
    `organise_campaign` has no Say. Covered by the money rule at `:12-15`, so cosmetic.

12. **Brand grep (`grep -i openhands plugins/ template/`)**, judged:
